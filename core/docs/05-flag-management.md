# 5. Flag Management

## Flag Format

All flags follow:
```
FEIT{<team>_<challenge>_<descriptor>_<random>}
```

Example:
```
FEIT{team1_web_source_flag_a3f9}
FEIT{team3_sqli_database_flag_7b2c}
```

- `<team>`: team1 through team5
- `<challenge>`: web, sqli, hidden, pcap, misconfig
- `<descriptor>`: brief description of where the flag is
- `<random>`: 4-8 hex characters for uniqueness

## Flag Generation

Flags are generated by `scripts/generate-flags.sh`:

```bash
#!/bin/bash
# Generates unique flags for all teams and challenges
# Output: flags/master-flags.json

TEAMS=5
OUTPUT_DIR="./flags"
mkdir -p "$OUTPUT_DIR"

declare -A CHALLENGES=(
    ["web_source"]="100"
    ["web_header"]="100"
    ["sqli_database"]="200"
    ["hidden_ftp"]="150"
    ["hidden_web"]="150"
    ["pcap_http"]="200"
    ["pcap_dns"]="200"
    ["redis_noauth"]="250"
    ["memcached"]="250"
)

echo "{" > "$OUTPUT_DIR/master-flags.json"
echo '  "flags": [' >> "$OUTPUT_DIR/master-flags.json"

FIRST=true
for TEAM_NUM in $(seq 1 $TEAMS); do
    for CHALLENGE in "${!CHALLENGES[@]}"; do
        RANDOM_SUFFIX=$(openssl rand -hex 4)
        FLAG="FEIT{team${TEAM_NUM}_${CHALLENGE}_flag_${RANDOM_SUFFIX}}"
        POINTS=${CHALLENGES[$CHALLENGE]}

        if [ "$FIRST" = true ]; then
            FIRST=false
        else
            echo "," >> "$OUTPUT_DIR/master-flags.json"
        fi

        printf '    {"team": "team%d", "challenge": "%s", "flag": "%s", "points": %s}' \
            "$TEAM_NUM" "$CHALLENGE" "$FLAG" "$POINTS" >> "$OUTPUT_DIR/master-flags.json"
    done
done

echo "" >> "$OUTPUT_DIR/master-flags.json"
echo "  ]" >> "$OUTPUT_DIR/master-flags.json"
echo "}" >> "$OUTPUT_DIR/master-flags.json"

echo "Flags generated: $OUTPUT_DIR/master-flags.json"
chmod 600 "$OUTPUT_DIR/master-flags.json"
```

## Master Flag List Storage

- File: `/opt/feit-ctf/flags/master-flags.json`
- Permissions: `0600` (root read/write only)
- NOT mounted into any student-accessible container
- Loaded into scoreboard database at deployment time
- Backed up with `scripts/backup.sh`

## Flag Rotation / Reset

To rotate flags between events:
1. Run `./scripts/generate-flags.sh` to create new flags
2. Run `./scripts/deploy-challenges.sh` to rebuild containers with new flags
3. Reset the scoreboard database: `./scripts/reset-scoreboard.sh`

The master flag list is the single source of truth. Challenge containers read flags from environment variables or baked-in files during build.

## Preventing Flag Tampering

### Baked-in Flags
Flags are embedded into Docker images at build time (via `COPY` or `ENV`), not mounted as volumes. Students cannot modify the flag source.

### Read-only Flags
Inside containers, flag files are owned by root with permissions `0444`.

### Integrity Monitoring
A host-side cron job checks flag integrity every 60 seconds:

```bash
#!/bin/bash
# /opt/feit-ctf/scripts/check-flags.sh
# Run via cron: * * * * * /opt/feit-ctf/scripts/check-flags.sh

MASTER_FLAGS="/opt/feit-ctf/flags/master-flags.json"

for TEAM in $(seq 1 5); do
    # Check web flag
    EXPECTED=$(jq -r ".flags[] | select(.team==\"team${TEAM}\" and .challenge==\"web_source\") | .flag" "$MASTER_FLAGS")
    ACTUAL=$(docker exec web-team${TEAM} cat /usr/share/nginx/html/index.html 2>/dev/null | grep -oP 'FEIT\{[^}]+\}')

    if [ "$EXPECTED" != "$ACTUAL" ]; then
        echo "$(date): Flag mismatch for team${TEAM} web_source. Restarting container."
        docker restart web-team${TEAM}
    fi
done
```

### Container Auto-restart
All challenge containers use `restart: unless-stopped`. If a student crashes a service, it comes back automatically.

### No Shell Access
Challenge containers do not expose SSH. Students interact only through the intended service ports (HTTP, FTP, Redis, etc.).
